# Разведка по соревнованию

Накоплено до 29 августа 2026. Всё, что помечено «гипотеза» — не проверено.

## Формат и метрика

| | |
|---|---|
| Задача | single-label классификация клипа, 40 классов, `action_id` 0–39 |
| Тест | 405 клипов |
| **Public LB** | **201 клип** |
| **Метрика** | **accuracy** |
| Сабмит | CSV, колонки `path,prediction`, порядок строк как в `test.csv` |
| `path` | `small_model_track_test/SM_test_0001/` |

**Как получено число 201.** Разности счетов на лидерборде кратны 0.004975 = 1/201.
Проверка: 0.98009=197/201, 0.97512=196/201, 0.91542=184/201, 0.91044=183/201,
0.90049=181/201, 0.89552=180/201, 0.86567=174/201, 0.83582=168/201 — сходится
до последнего знака. Отсюда же следует, что метрика — обычная accuracy.

**Следствие:** один клип = 0.5% на приватной половине. Лидерборд шумит на ±1–2%.
Гнаться за десятыми долями бессмысленно, нужна своя валидация.

## Данные

44.62 ГБ трейн (`HAR.z01`–`HAR.z08` по 5.37 ГБ + `HAR.zip` 1.67 ГБ),
2.79 ГБ тест. Датасет **gated** на HF.

```
Training: HAR/data/<modality>/<action>/<user>/<trial>/<files>
Testing:  small_model_track_test/<id>/<modality>/<files>
```

- Метка — префикс имени папки: `0_Wash_face` → `action_id` 0.
- `class_mapping.csv` читать с `encoding="utf-8-sig"` (BOM).
- `<user>` в пути → группировка для cross-subject CV бесплатно.
- Модальность — верхний уровень → выборочная распаковка возможна.
- **«Not every clip has every modality»** → modality dropout обязателен,
  на инференсе перенормировать веса по присутствующим веткам.
- **«Sampling rates differ»** → выравнивание своё. Ключи в именах файлов:
  `Depth_<datetime>_<idx>_Color.png`, `IR_<datetime>_<idx>.png`,
  `radar_output_T<ts>.csv`. У Thermal (`frame_000063.jpg`) таймстемпа нет —
  выравнивать долей от длины клипа.
- Depth_Color — **раскрашенная** глубина. Обратить colormap через LUT и вернуть
  скаляр. Публичное решение этого не делает, кормит RGB как есть.
- Подтверждено из кода: кадры 640×480.

## Правила — что на самом деле обязывает

Формальный раздел «Small Model Track · Additional Restrictions» содержит ровно три пункта:

1. No large pretrained backbones
2. No closed-source APIs or LLMs for development
3. No API / LLM labeling of training data

**Архитектурного ограничения там нет.** «CNN / RNN / Transformer» встречается
только в сводной карточке и в прозе как *encouraged*. GCN (ST-GCN, CTR-GCN)
проходит; если нужна бумага — спросить на форуме Kaggle.

100 МБ обязывают, хотя тоже только из карточки. Запас огромный: 3D-CNN+BiGRU =
2.77M параметров = 10.55 МБ; CTR-GCN = 1.4M. Квантование законно (правила про
точность молчат), но не понадобится: fp16 даёт ×2, этого хватит с избытком.

Три пункта — зеркало правил Large Model Track («Any pretrained model allowed»,
«Closed-source APIs encouraged», «LLM-based pseudo-labeling permitted»).
Отсюда и упоминание LLM. Смысл запрета — не протаскивать дистилляцию LVLM
в маленькую модель.

## Лидерборд

- Топ: 0.98009 / 0.98009 / 0.97512, затем **обрыв** до 0.91542. Разрыв ~4σ,
  подгонкой под 201-клиповый LB не объясняется.
- Лучшее публичное решение: **0.716**.
- Probing отпадает: у 5-го места 129 сабмитов и всего 0.910.

**Главная гипотеза (не проверена):** в тренировочном архиве лежат пользователи
10/11/25/26, объявленные тестовыми. Основание — пример в карточке HF:
`HAR/data/IR/0_Wash_face/user10/4-2-1/`. Если так, обучившиеся на них получают
same-subject тест вместо cross-subject, что и даёт 0.98. Проверяется скриптом
`code/data/inventory.py` за 1.67 ГБ.

Организаторы, похоже, про это знают: на Zoom-верификации sample data состоит из
**seen + unseen субъектов (Part A + Part B)** — конструкция, осмысленная только
как детектор эксплуатации пересечения субъектов.

## Публичные ноутбуки (лежат в notebooks/reference/)

**`yolo-for-cuhk-x.ipynb` — настоящий, LB 0.716.** Inference-only, веса из
приватного датасета. YOLO11n → кроп → 16 кадров 128×128 → R(2+1)D-34 →
ансамбль 2 фолдов → TTA 4 прохода → argmax.

- Использует **2 модальности из 6** (Depth_Color + IR = 4 канала). Skeleton,
  IMU, Thermal, mmWave не тронуты вообще. Вот где твой прирост.
- Локальная subject-CV = [0.7156, 0.7187], LB = 0.716 → **валидация по
  отложенным субъектам предсказывает LB точно**. Главный вывод из ноутбука.
- Нарушает правила: R(2+1)D-34 предобучен на IG65M, бэкбон заморожен. В бандле
  лежит `IG65M_LICENSE.md`. Веса ужаты в int5/int6 ровно под кэп 100 МБ
  (93 688 142 байт, есть хардкод-ассерт).
- Плюс лицензионная мина: Ultralytics YOLO под **AGPL-3.0**, несовместимо с
  обязательством финалистов открыть код под Apache 2.0.
- Детекция промахнулась на 10 клипах из 405, 8 остались без кропа вовсе.
  Bbox из скелета даст 0 промахов и бесплатно.
- Незакрытая дыра: `soft-count imbalance: 50.53` при пороге «>2 — чини».
  argmax выдаёт 23 клипа на класс 7 и 2 клипа на класс 23 при ожидаемых ~10.
  Балансировка под равномерный приор (Sinkhorn / венгерский) стоит несколько
  пунктов поверх любой модели.
- В датасете к нему лежат `MODEL_CARD.md`, `recipe.json`, `RESEARCH_HANDOFF.md`
  — там рецепт обучения, которого нет в самом ноутбуке. Посмотреть.

**`cuhk-x-har-edge-optimized-3d-cnn-bigru-network.ipynb` — фальшивка.**
Не открывает ни одного файла данных. Датасет возвращает синтетический кружок,
трейн-выборка — тройной цикл из несуществующих путей, «EDA» построена на
вписанных руками числах (`completeness_ratios = [1.00, 0.98, 0.95, 0.92, 0.45,
0.38]` — выдумка, выглядящая как ответ на важный вопрос). Val accuracy = 0.0250
= 1/40 все 25 эпох, лосс = 3.689 = ln(40). Сабмит — константа (все 405 = класс 2).

Полезен только каркасом: 3D-CNN → `AdaptiveAvgPool3d((None,1,1))` → permute
`(B,T,C)` → BiGRU. Но перекос ёмкости: **64% параметров в GRU, 31% в стволе** —
для зрения вывернуто, при переиспользовании перелить в свёртки.

**Фильтр для таких ноутбуков:** открывается ли хоть один файл; двигаются ли
числа (лосс на `ln(n_classes)` = обучения не было); графики считаются или
вписаны; `min == max` в сабмите; совпадает ли markdown с кодом под ним.

## План

**Сначала EDA — [eda.md](eda.md). Это гейт, а не разминка:**
здесь отобран рычаг масштаба, а лидерборд из 201 клипа не измеряет мелких
улучшений, поэтому отдача лежит в понимании данных. Публичные 0.716 — цена
того, что автор не задал вопросов про модальности и артефакты.

1. `inventory.py` → развилка по пользователям 10/11/25/26.
2. Матрица доступности модальностей по тесту.
3. Cross-subject CV (`GroupKFold` по user) — главный прибор, а не LB.
4. MiniRocket на IMU — калибровка за вечер (разведка, не в сабмит).
5. Скелет: ST-GCN → CTR-GCN, 4 потока. Соответствует правилам, с нуля, 1.4M.
6. Depth/IR: ResNet-18 + TSM с нуля, кроп из скелета, обращённый colormap.
7. Thermal тем же пайплайном — сильнейшая одиночная модальность.
8. Late fusion + modality dropout + коррекция приора.
9. mmWave — только если останется время.

Цель: **0.75+ на своей cross-subject валидации.**
