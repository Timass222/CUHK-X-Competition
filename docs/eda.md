# EDA — обязательный этап, не формальность

На этом соревновании **EDA и есть основной рычаг**. Масштаб отобран правилами
(нет претрейна, кэп 100 МБ), тюнинг архитектуры внутри ветки не измеряется
(201 клип на публичном LB, один клип = 0.5%). Отдача лежит в том, что ты
узнаешь про данные: какие модальности реально есть, как они выровнены, что
кодирует `<trial>`, есть ли артефакты. Лучшее публичное решение получило 0.716
на двух модальностях из шести именно потому, что автор не задал этих вопросов.

**Правило: ни одна модель не пишется, пока не пройден блок 1.**

**Анти-паттерн.** `notebooks/reference/cuhk-x-har-edge-optimized-*.ipynb` —
пример того, как делать нельзя: там «EDA» построена на вписанных руками числах
(`completeness_ratios = [1.00, 0.98, 0.95, 0.92, 0.45, 0.38]`), а выводы поданы
как факты. Каждое число в нашем EDA должно быть вычислено из файлов. Хардкод-
список, идущий прямо в `plot()`, — запрещённая конструкция.

## Блок 0 — опись архива (1.67 ГБ, до скачивания остальных 43 ГБ)

`python code/data/download.py probe && python code/data/inventory.py data/raw/HAR.zip --json data/meta/inventory.json`

| # | Вопрос | Что меняет |
|---|---|---|
| 0.1 | **Есть ли в трейне пользователи 10, 11, 25, 26?** | Если да — тест становится same-subject, объясняется кластер 0.98, стратегия перестраивается целиком. Скрипт печатает вывод явно |
| 0.2 | Какие модальности, сколько файлов и байт в каждой | План выборочной распаковки; сразу видно, стоит ли вообще трогать Radar |
| 0.3 | **Что кодирует `<trial>` вида `4-2-1`?** Распределение каждой компоненты | Если первая принимает 2 значения — это помещение. Открывает leave-one-environment-out валидацию |
| 0.4 | Сколько distinct clips всего, сколько на пользователя | Размер твоей валидации; сравни с 201 клипом публичного LB |
| 0.5 | Список 40 классов, клипов на класс | Сбалансирован ли трейн; понадобится для коррекции приора |
| 0.6 | Клипов на пару (модальность × пользователь) | Есть ли пользователи с дырами в модальностях |

## Блок 1 — тест (2.79 ГБ) · ГЕЙТ, без этого не кодить

| # | Вопрос | Что меняет |
|---|---|---|
| 1.1 | **Матрица `clip × modality`: какие модальности есть у каждого из 405 клипов** | Самый важный факт соревнования. Определяет, какие ветки вообще имеет смысл строить и насколько агрессивным должен быть modality dropout |
| 1.2 | Отсортирован ли `test.csv`? Связаны ли соседние строки? | Проверка на лик. Если соседи одного класса — сглаживание даёт бесплатные пункты (и объясняет 0.98) |
| 1.3 | **Распределение числа кадров по клипам** | Фиксированные 16 кадров или адаптивная выборка; плюс см. 1.4 |
| 1.4 | **Предсказывает ли длина клипа класс?** Обучи тривиальный классификатор только на метаданных: `(n_frames, набор модальностей, размеры файлов)` | Если он бьёт случайность заметно — это бесплатный сигнал и одновременно предупреждение об артефакте датасета. Дешёвый, обязательный тест |
| 1.5 | Есть ли в именах файлов тестовых клипов таймстемпы, выдающие сессию или пользователя | Ещё один канал лика; также ключ для выравнивания модальностей |
| 1.6 | Совпадает ли структура тестового клипа с тренировочным | Один загрузчик на оба или два |

## Блок 2 — реальность каждой модальности

Прогонять по мере распаковки, начиная с лёгких (Skeleton, IMU).

| # | Вопрос | Что меняет |
|---|---|---|
| 2.1 | **Depth_Color: какая палитра?** Построй отображение RGB → скаляр, проверь обратимость | Обращение colormap возвращает метрическую глубину в 1 канале. Публичное решение кормит RGB как есть — это упущение, а не оптимизация |
| 2.2 | **Skeleton: сколько суставов, какой формат, система координат (пиксели или метры), доля пропущенных/нулевых** | Основная ставка. Заодно даёт bbox бесплатно — проверь, что он адекватен |
| 2.3 | **IMU: частота, число каналов на сенсор, куда крепились 5 датчиков, единицы, дрейф** | Определяет длину окна и архитектуру 1D-ветки |
| 2.4 | **Radar: облако точек или range-doppler? Точек на кадр?** | Решает, PointNet-подход или спектрограмма + 2D CNN. Скорее всего вообще не трогаем |
| 2.5 | IR / Thermal: динамический диапазон, доля чёрных и битых кадров | В публичном ноутбуке нашлось 64 битых IR-кадра — загрузчик обязан это переживать |
| 2.6 | **Частоты дискретизации по модальностям**; работают ли таймстемпы в именах как ключ выравнивания | У Thermal (`frame_000063.jpg`) таймстемпа нет — выравнивать долей от длины |
| 2.7 | Присутствие модальностей по клипам **в трейне** (не только в тесте) | Тренировочная и тестовая доступность могут различаться |
